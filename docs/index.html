Pagi store build

A Shopify build for a fictional brunch café in Bali that wants its own online ordering instead of paying a delivery app's commission. Dishes with add-ons, pickup and delivery times limited by what the kitchen can cook, a kitchen board, and catering quotes, in English and Bahasa Indonesia.

Chapters

The problem

Commission on every order

Delivery apps take a large share of each order. A Shopify store keeps the margin, the customer list and the payouts.

A kitchen has a limit

Twelve dishes per quarter hour, not unlimited. Taking more than that means cold food and angry tables.

Brunch is customised

Poached or scrambled, sourdough or gluten-free, extra bacon. Every choice has to reach the kitchen and the price.

What it shows

Shopify Functions

  • Cart Transform (lineExpand) for add-ons
  • Checkout Validation with its settings in a metafield
  • One shared rules module, tested once, used by both

Backend

  • Webhooks with HMAC checks, queue and retries
  • App proxy endpoints with signature checks
  • Kitchen board, draft orders, GDPR topics

Storefront

  • Custom theme, EN and ID with translated products
  • Slot picker that saves cart attributes
  • Seed script for a dev store via the Admin API

UI & design system

The interface is documented in Figma: 26 variables whose names match the theme's CSS custom properties, 11 text styles, the component set (time slots, add-on options, menu rows, kitchen tickets and more) and the key screens on mobile, desktop and the kitchen tablet, in English and Bahasa Indonesia.

Trade-offs, said plainly

  1. Capacity is enforced at checkout, not reserved. Two customers can pass checkout for the last seats in a slot within the same minute. The board flags any slot that goes over, and the kitchen decides.
  2. Apps exist for this. Pickup-scheduling apps cover hours and dates. This build is for when the limit is dishes per slot and the add-ons must be priced, which those apps don't do together.
  3. Not yet run on a live store. Everything here runs in tests and the demo. The add-on line expansion and the checkout messages still need a check on a Shopify development store before launch.
